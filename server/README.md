# API и структура db.json

Запуск: из корня проекта `npm run server` (запускается кастомный сервер `server/index.mjs`, а не CLI json-server). В нём добавлен обработчик **PUT /tasks** с телом-массивом для полной замены списка задач (в стандартном json-server на это 404).

## Структура db.json

Корневые ключи — ресурсы json-server, **значения — массивы** (без вложенного `data`):

```json
{
  "tasks": [ { "id": 1, "name": "...", ... } ],
  "projects": [ ... ],
  "users": [ ... ]
}
```

- **GET /tasks** — весь массив задач.
- **GET /tasks/:id** — одна задача (роут `tasks/:id`).
- **POST /tasks** — создание (тело — объект без `id`).
- **PATCH /tasks/:id** — частичное обновление (минимальный размер запроса).
- **DELETE /tasks/:id** — удаление.
- **PUT /tasks** — замена всего массива (например, после drag-drop); тело — массив задач.

## Оптимизация при 1000+ задачах

| Действие              | Метод              | Запросы / размер ответа |
|-----------------------|--------------------|--------------------------|
| Список (с пагинацией) | GET /tasks?_page=1&_limit=20 | Один запрос, только страница |
| Одна задача           | GET /tasks/:id     | Один запрос, один объект |
| Создание              | POST /tasks        | Один запрос, в ответе — созданная задача |
| Обновление поля       | PATCH /tasks/:id   | Только изменённые поля в теле и в ответе |
| Удаление              | DELETE /tasks/:id  | Без тела |
| Смена порядка (DnD)   | PUT /tasks         | Один запрос с полным массивом (использовать только для порядка) |

Пагинация: в `taskService.getTasks()` уже заложены параметры `GetTasksParams` (`page`, `limit`, `sort`, `order`) для последующего подключения `?_page=&_limit=` и заголовка `X-Total-Count`.
