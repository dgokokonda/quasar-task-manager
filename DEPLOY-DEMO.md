# Демо: бесплатный хостинг (анализ + инструкция)

Коротко: **Firebase для этого проекта не подходит** (причины ниже), зато подходит **GitHub Pages + демо-режим с mock API в браузере**, который уже реализован в репозитории. Ниже — разбор, инструкция деплоя и альтернативы, доступные из РФ без VPN.

---

## 1. Почему Firebase не получается

Проект состоит из SPA (Quasar/Vite) и бэкенда `server/index.mjs` (tinyhttp + json-server-подобная логика: `routes.json`, `config.json`, данные в файле `server/db.json`).

| Что проверяли                                          | Итог                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Firebase Hosting                                       | Только статика/SPA. Фронт разместит, бэкенд — нет (нужен динамический рантайм).                                                                                                                                                                                                                                                                                                                                                    |
| Cloud Functions 2nd gen, App Hosting, Cloud Run        | Требуют тариф **Blaze** с привязанным billing-аккаунтом Google Cloud. Google с 2022 года не предоставляет billing пользователям из РФ, то есть Blaze без иностранной карты недоступен. «Бесплатного» пути туда нет.                                                                                                                                                                                                                |
| Cloud Functions 1st gen (остались на бесплатном Spark) | Формально доступны без карты, лимит — сотни тысяч вызовов в месяц. Но: (а) 1st gen снят с активной поддержки (отключение — февраль 2027); (б) у Functions нет постоянного диска: файловая система эфемерная, писать можно только в `/tmp`, инстансов может быть несколько. Наш сервер при каждой мутации пишет в `server/db.json`, а при старте читает его → состояние демо не переживёт рестарты и «разъедется» между инстансами. |
| Firestore / Realtime Database вместо `db.json`         | Персистентность решает, но это **переписывание бэкенда**: `routes.json`/`config.json` неприменимы, фильтрация/сортировка/пагинация (`db.filters`, `_page`/`_limit`, дельта `order`) уезжают в Security Rules и клиентские запросы. Для демо «за час» — нет.                                                                                                                                                                        |

Вывод: с Firebase можно работать, только если одновременно (1) брать Blaze с иностранной картой или мириться с 1st gen, и (2) переносить хранение данных из файла в Firestore + правила. Это дороже по времени, чем вся текущая серверная часть.

Дополнительный минус для РФ: доступность `*.web.app` / `*.firebaseapp.com` и `console.firebase.google.com` нужно проверять в момент публикации — Google-сервисы периодически частично ограничиваются.

## 2. Что сделано в репозитории: демо без сервера

Реализован mock API **в браузере**, который отвечает на те же `/api/*`, что и `server/index.mjs`. Клиентский код (`src/services/*`, `src/stores/*`, `baseUrl = '/api'`) не менялся.

| Файл                                                    | Назначение                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/mock/db.ts`                                        | Хранилище: сид + состояние в `localStorage` (ключ `ppm-demo-db`), debounce-сохранение, `resetMockDb()`.                                                                                                                                                                                                                                                                                 |
| `src/mock/handlers.ts`                                  | Маршруты и логика: `GET /tasks` (фильтры + сортировка + `_page`/`_limit`, ответ в форме `{ data, pageData }`), `GET /tasks/:id`, `POST/PUT/PATCH/DELETE /tasks*`, `PATCH /tasks/order` (дельта drag&drop), `PUT /filters/apply`, `GET /filters`, `GET /projects`, `GET /users`. Фильтрация и компараторы скопированы из `server/index.mjs`, поэтому поведение совпадает с дев-сервером. |
| `src/mock/fetchInterceptor.ts`                          | Подмена `globalThis.fetch`: перехватываются только запросы на тот же origin с путём `/api/...` (с учётом `publicPath`); остальное уходит в настоящую сеть.                                                                                                                                                                                                                              |
| `src/mock/mode.ts`                                      | Режимы mock API (`off` / `intercept` / `fallback`) и probe живости бэкенда.                                                                                                                                                                                                                                                                                                             |
| `src/boot/mock-api.ts`                                  | Включение демо-режима (порядок boot: `['mock-api', 'pinia', 'echarts']`).                                                                                                                                                                                                                                                                                                               |
| `public/mock/db.json`                                   | Сид демо (копия `server/db.json` без служебного `pageData`; объём данных совпадает с серверной базой).                                                                                                                                                                                                                                                                                  |
| `scripts/generate-demo-seed.mjs`                        | Пересид `server/db.json` → `public/mock/db.json` (`npm run seed:demo`).                                                                                                                                                                                                                                                                                                                 |
| `scripts/build-demo.mjs`                                | Кроссплатформенная прод-сборка демо: ставит `PUBLIC_PATH`, `ROUTER_MODE`, `VITE_MOCK_API=true`, вызывает `quasar build`, делает `dist/spa/404.html` (SPA-fallback для GitHub Pages).                                                                                                                                                                                                    |
| `scripts/serve-demo.mjs`                                | Локальный предпросмотр `dist/spa` со SPA-fallback (`npm run preview:demo`).                                                                                                                                                                                                                                                                                                             |
| `scripts/dev-all.mjs`                                   | `npm run dev:all` — `quasar dev` и `server/index.mjs` в одном терминале (логи с префиксами `[web]`/`[api]`).                                                                                                                                                                                                                                                                            |
| `scripts/smoke-mock.mjs`, `scripts/mock-smoke-entry.ts` | Смоук-тест mock API без браузера (`npm run test:mock`): пагинация, фильтры, сортировка, CRUD, дельта `order`, разбор URL, выбор режима mock API и probe бэкенда.                                                                                                                                                                                                                        |
| `.github/workflows/deploy-demo.yml`                     | Сборка и публикация на GitHub Pages.                                                                                                                                                                                                                                                                                                                                                    |
| `netlify.toml`                                          | Тот же демо-билд для Netlify (`DEMO_BASE=/`, publish `dist/spa`, SPA-редирект).                                                                                                                                                                                                                                                                                                         |
| `.env.production`, `.env.development`                   | `VITE_MOCK_API=true` для прод-сборки, `VITE_MOCK_API=fallback` для `npm run dev` (реальный бэкенд, при его отсутствии — мок).                                                                                                                                                                                                                                                           |

Как включается демо-режим (`VITE_MOCK_API` или параметры URL):

| Значение                      | Поведение                                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| `true` / `?mock=on`           | всегда мок — используется в прод-демо (`npm run build:demo`, `.env.production`);                         |
| `fallback` / `?mock=fallback` | реальный бэкенд; если `:3000` недоступен — мок. Это значение по умолчанию в dev (`.env.development`)     |
| `false` / `?mock=off`         | только реальный бэкенд (обязателен `npm run server`);                                                    |
| `?resetDemo=1`                | сбросить состояние демо в `localStorage` к исходному сид-файлу (параметр после сброса убирается из URL). |

Почему в dev раньше «падают все запросы»: пока `npm run server` не запущен, Vite-прокси отвечает на `/api/*` статусом **500** с текстом `Error occurred while trying to proxy` — это не ошибка приложения. В `fallback`-режиме probe-запрос (`GET /api/users`) это замечает, в консоли появляется предупреждение `[mock-api] …`, и дальше запросы обслуживает мок. Варианты запуска: `npm run dev:all` (фронт + бэкенд одной командой), два терминала (`npm run dev` + `npm run server`), либо `npm run dev` без бэкенда — тогда данные демо.

Осознанные отличия от реального сервера (на поведение UI не влияют):

- служебный ключ `pageData` в базу не пишется, в mock он считается на лету;
- некорректные `_page`/`_limit` трактуются как значения по умолчанию, а не как `NaN`;
- не поддерживается `POST /api/upload` — на сервере такого маршрута тоже нет, и в UI `uploadService` нигде не вызывается (заготовка на будущее).

Минусы демо-режима (важно для демонстрации):

- изменения видны только в этом браузере: между посетителями данные **не общие** (серверной БД нет);
- состояние живёт в `localStorage` (при переполнении квоты демо работает, но не сохраняет);
- сид ~400 КБ (GitHub Pages и остальные статиальные хостинги отдают его со сжатием).

Если нужны общие для всех посетителей данные — см. раздел 4.

## 3. Деплой на GitHub Pages (рекомендуемый вариант)

GitHub и `*.github.io` в РФ доступны без VPN. Квоты Pages (1 ГБ на сайт, ~100 ГБ/мес исходящего трафика) для демо заведомо достаточны; актуальные цифры — <https://docs.github.com/pages/getting-started-with-github-pages/about-github-pages>.

1. Репозиторий публичный: `https://github.com/dgokokonda/quasar-task-manager`.
2. В репозитории один раз: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy-demo.yml` запускается на push в `main` (сейчас активна ветка `chart-feature` → смержить или запушить в `main`) либо вручную: Actions → «Deploy demo (GitHub Pages)» → Run workflow.
4. Сайт: `https://dgokokonda.github.io/quasar-task-manager/`.

Публичный путь `/quasar-task-manager/` задаётся в workflow (`GH_PAGES_BASE: /${{ github.event.repository.name }}/`, поддерживает и `DEMO_BASE`). Для другого репозитория или корневого домена менять только эту переменную (`DEMO_BASE=/`).

Проверка ровно той сборки, которая уйдёт на Pages:

```bash
npm run seed:demo       # перегенерить public/mock/db.json из server/db.json
npm run build:demo      # сид + quasar build + dist/spa/404.html
npm run preview:demo    # http://localhost:5000/quasar-task-manager/
npm run test:mock       # смоук-тест mock API (пагинация/фильтры/CRUD/drag&drop)
```

`npm run build` (без `:demo`) собирается с `publicPath: '/'` — для Pages project site так не публикуемся, там нужен `build:demo`.

Deep-links (`.../quasar-task-manager/tasks/123`) на Pages работают за счёт `404.html` (его делает `build-demo.mjs`). Если хочется без этой зависимости — собирать с `ROUTER_MODE=hash` (URLы станут `#/tasks/123`); синхронизация фильтров и пагинации с URL при этом не ломается.

## 4. Если нужен настоящий бэкенд (общие данные для всех посетителей)

Статикой с mock уже не обойтись. Варианты, которые стоит рассматривать из РФ без VPN (квоты и требования к карте меняются — проверять на страницах тарифов):

| Хостинг                                                                 | Что даёт бесплатно                                                                                                                              | Что дорабатывать                                                                                                                                                                      | Доступность из РФ без VPN                                                                                                                                                                                                         |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Netlify** (`netlify.toml` уже добавлен)                               | статика/SPA, ~100 ГБ трафика/мес, SPA-fallback из коробки                                                                                       | ничего: `DEMO_BASE=/ npm run build:demo`, publish `dist/spa`                                                                                                                          | как правило да (`*.netlify.app` не блокировался), проверить у провайдера                                                                                                                                                          |
| **Cloudflare Pages / Workers**                                          | Pages: трафик без лимита, 500 билдов/мес; Workers: 100 тыс. запросов/сут                                                                        | SPA-fallback настраивается в конфиге; реальный бэкенд потребует переноса `server/index.mjs` на модель `Request/Response` (node:http-сервер напрямую не запускается), данные — в KV/D1 | `*.pages.dev` обычно доступен; **важно**: Cloudflare с августа 2025 не выдаёт интерактивные challenge посетителям из РФ, поэтому включённый Bot Fight Mode / Under Attack может закрыть доступ из РФ (по умолчанию они выключены) |
| **Vercel (Hobby)**                                                      | статика/SPA, трафик-квота, SPA-fallback через `vercel.json`                                                                                     | ничего; Hobby запрещён для коммерческого использования                                                                                                                                | `*.vercel.app` обычно доступен, проверить                                                                                                                                                                                         |
| **Render (Free web service)**                                           | Node-процесс в контейнере, ~512 МБ, усыпление после ~15 мин простоя (холодный старт ~1 мин)                                                     | сервер запускается как есть (`node server/index.mjs`), но диск эфемерный: правки в `db.json` теряются при рестарте/деплое (нужен платный Disk или сид при старте)                     | как правило да                                                                                                                                                                                                                    |
| **Koyeb / Zeabur / Fly.io**                                             | бесплатные веб-сервисы с жёсткими лимитами; у Fly и часто у Koyeb требуется способ оплаты                                                       | то же, что с Render                                                                                                                                                                   | нестабильно, проверять                                                                                                                                                                                                            |
| **Supabase (Free)**                                                     | Postgres + REST API из коробки (PostgREST), Auth, Storage — ближе всего к «бесплатному бэкенду»                                                 | маршруты другие (`/rest/v1/tasks?...`), пагинация/фильтрация не совпадают с json-server → править `src/services/*`; бесплатные проекты без активности «засыпают», их нужно будить     | `*.supabase.co` обычно доступен                                                                                                                                                                                                   |
| **Российские облака** (Yandex Cloud, Selectel, Timeweb Cloud, VK Cloud) | постоянного бесплатного тарифа для контейнеров нет; есть пробные кредиты (например, кредитный период Yandex Cloud) и минимальные платные тарифы | сервер в Docker/VPS запускается без изменений                                                                                                                                         | да, без VPN                                                                                                                                                                                                                       |

Самый дешёвый по трудозатратам путь с «живым» бэкендом: тот же `server/index.mjs` в контейнере на Render/Koyeb с сидом `server/db.json` при старте (данные живут до перезапуска инстанса). Для демонстрации на несколько часов хватает, но URL будет «просыпаться» после простоя, а правки разных посетителей друг у друга не увидятся. Именно поэтому для демо выбран вариант с mock API: он убирает сервер целиком.

## 5. Чек-лист после публикации и что не забыть

После деплоя проверить с обычного браузера (без запущенного `npm run server`):

1. список задач грузится, пагинация листается, сортировка по колонкам работает;
2. фильтры по статусу/типу работ/исполнителю и поиск применяются, в том числе после перезагрузки страницы (фильтры хранятся в состоянии демо);
3. drag&drop меняет порядок/статус, после F5 порядок сохраняется;
4. создание, редактирование и удаление задачи работает и переживает перезагрузку;
5. прямой переход по ссылке на задачу (`.../quasar-task-manager/tasks/<id>`) открывается;
6. `?resetDemo=1` возвращает исходные данные;
7. если что-то не работает — в консоли браузера ищите префикс `[mock-api]`; часть логов в прод-сборке вырезается настройкой `drop_console`, поэтому удобно смотреть `npm run dev` с `?mock=on`.

Что учесть перед публичной раздачей ссылки:

- **данные публичные**: в `public/mock/db.json` (и в `server/db.json`) лежат ФИО исполнителей и названия проектов. Для публичного демо лучше собрать обезличенный сид — `npm run seed:demo` берёт `server/db.json`, поэтому достаточно подменить данные в нём или отредактировать `public/mock/db.json`;
- авторизации нет ни в дев-сервере, ни в демо — для тестового задания это ожидаемо, но публичную ссылку не стоит выдавать как «рабочий инструмент»;
- изменения в демо видит только тот браузер, где они сделаны (общей БД нет) — об этом полезно предупредить тех, кому отправляете ссылку;
- `server/db.json` и `public/mock/db.json` (~430 КБ) хранятся в git, каждый пересид даёт большой диф. Если это мешает, `public/mock/db.json` можно не коммитить и генерировать только в CI — `build:demo` делает это сам.

## 6. Итоговый ответ на вопрос

- **Firebase — не получится** без переписывания серверной части: Hosting умеет только статику, динамические сервисы Firebase (Cloud Functions 2nd gen, App Hosting, Cloud Run, Firestore) требуют Blaze с billing-аккаунтом Google Cloud, который в РФ недоступен; оставшиеся на бесплатном Spark Functions 1st gen не имеют постоянного диска, а текущий сервер живёт на записи в `server/db.json`.
- **Рабочий вариант, уже реализованный в репозитории**: GitHub Pages (`https://dgokokonda.github.io/quasar-task-manager/`) + демо-режим с mock API в браузере. Сервер для демо не нужен, состояние сохраняется у посетителя, поведение совпадает с дев-сервером.
- **Запасные бесплатные варианты без VPN из РФ**: Netlify (готовый `netlify.toml`), Cloudflare Pages (с оговоркой про bot protection для РФ-трафика), Vercel Hobby — для этого проекта они эквивалентны Pages, потому что бэкенд уже в браузере. Нужен именно сервер с общими данными — Render/Koyeb (усыпление + эфемерный диск) или Supabase (потребуется адаптация `src/services/*`).
